# Agent trial: the chaining commands, 2026-09-30

Do fresh agents follow the ids the new commands print from one hop to the
next? Three of the seven flows in `docs/plans/chains.md`, each given to a
fresh Sonnet 5.5 and Haiku 4.5 session with only the tool's path, against the
contoso world (loose matching), as
[How to run agent trials](../how-to/run-agent-trials.md) describes.

## What the rounds found

- **The harness lied, not the tool.** Loose matching answered an unrecorded
  file with the closest recording on the same URL path, `OrderClient.cs` for
  `IOrderClient.cs`, and an unrecorded code search with another search's
  hits. Exchanges now list the fields that name what is asked for (`exact`:
  `path`, `scopePath`, `searchText`), which loose matching never substitutes:
  an unrecorded file is a 404, an unrecorded search finds nothing.
- **Agents reach for the pieces as flags.** Both models tried `ado file get
  PATH --repo api` before the id; it works now. A `--path` flag and two
  positionals (`api src/x.cs`) were tried once each and corrected from the
  usage error.
- **A computed field is not a signpost.** `task logs` printed `at`, but Haiku
  never asked for that field and so never found `source get`. A note naming
  the next command (`[the failing line in the DAG's code: …]`) sent both
  models straight there.
- F1's chain worked from round 1: `thread list` printed `436/7`, and
  `thread comment 436/7 … --resolve` closed it in one call. Haiku first tried
  a `--text` flag (exit 2, corrected).
