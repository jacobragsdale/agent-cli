# Agent trial, 2026-10-07: confluence and aisearch

The first trial of the two new domains, run as
[How to run agent trials](../how-to/run-agent-trials.md) describes, against
the contoso world. Neither domain has met a live service with credentials
yet. Confluence's reads ran against a public Cloud site anonymously while it
was built, and AI Search's world comes from the REST spec's examples.

## Setup

- **Binary:** the fixtures build of `175ee45`, behind the logging wrapper,
  with loose matching.
- **Runs:** ten tasks, each once on Sonnet 5.5 and once on Haiku 4.5, as
  headless sessions outside the repository. Every run had a working
  directory of its own.
- **Prompt:** the how-to's prompt, naming Confluence and AI Search among the
  services.

## Findings and changes

**1. The harness answered badly** (most of t02, t04 and t05's calls).
- **Searches:** the world recorded four Confluence searches, none of them
  for the release notes. Every search for "release notes", "v1.4.2" or a
  title got the runbooks back from loose matching.
- **Versions:** only version 2 of page 1201 was recorded.
- **Filters:** an AI Search query answered the same three orders whatever
  its filter.

Recorded since:
- the searches agents made: by words, by title, and unfiltered;
- versions 1 and 3 of page 1201;
- space OPS, and a title that finds no page (Cloud answers an empty list);
- a search filtered on `status eq 'delayed'`.

**2. The tool could point better.**
- **A page ref that is words** (`page get v1.4.2`, or `page get v1.4.2
  release notes`) now gets a hint naming `confluence page list` with those
  words, all of them when several were passed. Before, it said `page list
  TEXT`.
- **An index and a key as two words** (`aisearch document get orders
  88123`) now names `aisearch document get 88123 --index orders`.
- **No more empty list before an error:** when every id of several failed,
  an empty list printed on stdout ahead of the error. `Failure::with_data`
  now drops an empty list, in every domain.

**3. Search sent agents astray.**
- **"release notes"** ranked ado's approvals first, and **"runbook"** ranked
  `confluence page create`.
- **Changes:**
  - `page create` no longer carries the keyword "runbook";
  - `page list`'s summary names runbooks;
  - `page comment` answers to "add", and `comment update` no longer
    prefix-matches it through "addressed".
- **Now:** "release notes" lands on Confluence's page commands and "runbook"
  on `page list`.
- **Queries:** the agents' searches joined the labeled queries. Two of them
  still don't rank first: "release notes for v1.4.2" and "runbook for an
  order missing its customer id". Making `page list` win "release notes"
  outright would cost three queries that mean a page's other commands.

A second round was not run. The changes were checked in the world instead:
each of the paths above now answers as the tasks expect.
