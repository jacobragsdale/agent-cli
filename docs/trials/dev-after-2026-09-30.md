# Development trial after the refactor, 2026-09-30

The three development tasks of the
[baseline](dev-baseline-2026-09-30.md), run again after `REFACTOR_PLAN.md`
Phases 1 to 3: per-domain search queries, reference pages, world tests and
facts; crate cards, context rules, `scripts/check.sh`, `scripts/new-command.sh`
and the `agent-cli-dev` skill; one file per command. Same prompt, same model,
same seeding, fresh worktrees of `bb2572c`.

**In short:** every run passed the five checks, no agent read history or
generated files, and tool calls fell by about a quarter. The token target
is met by the plan's one run per task (29% below the baseline) but not by
two runs per task (18%), because two runs of one task differ by as much as
the refactor saves. D2 still edits `scripts/fake/kubectl`, outside its crate.

## Setup

As in the baseline: a fresh `claude -p` session per task with Sonnet 5.5,
from a worktree whose `target/debug` held built dependencies and no
workspace crates, four build jobs, the rust-analyzer plugin off, one task at
a time. The tree now carries `.claude/settings.json` (reading
`docs/reference/`, `Cargo.lock` and `target/` denied) and the skill.

Each task was then run a second time, and the baseline's D3 once more, to
see how far one run of a task wanders. The baseline already had a second
run of D1 and D2 (the ones whose worktrees held an earlier attempt's build
output; tokens do not depend on that).

## The plan's success criteria

| Criterion | Result |
|---|---|
| Every run passes all five checks | Met: all six after-runs |
| Files outside the task's crate are only its fixtures, facts, world test and reference page | Met for D1 and D3. **Not met for D2**: both runs changed `scripts/fake/kubectl`, whose built-in deployments had no labels to select on |
| Median tokens per task at least 25% below the baseline | Met by one run per task (−29%). **Not met** by two runs per task (−18%) |
| No run reads `PLAN.md`, `docs/plans/` or the generated reference | Met: every file each run read is listed below |

Why tokens fell less than reading did: each model call carries about 27,000
tokens before the agent reads anything (the system prompt, the user's and
the repo's instructions, the skill list), and a task makes 7 to 13 calls, so
most of a task's tokens are that fixed context sent again. The refactor cut
what agents read and cut the calls by about a quarter; the fixed part per
call barely moved (root `AGENTS.md` is 2.7 KB smaller). What would move it
further is fewer calls, and runs with three samples per task to tell a real
change from a lucky run (see `TODO.md`).

## Where the reading went

Before, every agent opened `docs/how-to/add-a-command.md` (19 KB) and then
its domain's big file: D3's first run printed all 922 lines of
`crates/airflow/src/run.rs`, its second read 330 lines of it in slices.

After, no run opened the how-to. Each read its crate's card, and D1 and D3
the skill and `scripts/new-command.sh`, then ran the script:

- **D1** read `crates/ado/AGENTS.md`, the skill, the two files of
  `pipeline/` (143 lines), `repo/get.rs` as the sibling to copy, and
  `lib.rs`; its second run also grepped `fixtures/world/http/ado.json` and
  recorded the world's answer, which its first run skipped.
- **D2** read `crates/k8s/AGENTS.md`, `deployment/list.rs` (the command,
  195 lines) and `pod/list.rs` (where `--label` already works), then the
  fake kubectl's deployments.
- **D3** read `crates/airflow/AGENTS.md`, the skill, `run/retry.rs` and
  `run/mod.rs`; its first run also looked at ado's `run/cancel.rs`, the
  same verb in another crate.

The skill was always read with `cat`, never loaded as a skill: its `paths`
make Claude Code offer it only after a matching file is touched, and root
`AGENTS.md` names it first. No run needed `docs/reference/`, and so none
hit the deny rule.

## Findings

- `scripts/fake/kubectl` holds the k8s tests' built-in cluster, so a k8s
  flag the fake does not know yet reaches outside the crate. Moving those
  built-in objects into a file under `crates/k8s/` that the fake reads would
  close it.
- Merging the parallel crate splits conflicted once, in
  `scripts/large-files.txt`, where the azure and airflow splits each dropped
  adjacent lines. It was the only conflict in six merges, in a file the plan
  expects them to touch.
- Two tasks show choices that vary run to run rather than with the layout:
  D3 refused a finished run with exit 5 in the baseline's first run and
  left it alone with exit 0 in the first run after; D1 recorded the world's
  answer in three of its four runs.
- Wall time did not fall: `scripts/check.sh --all` rebuilds the workspace
  with and without the fixtures feature, as the five checks did before.
